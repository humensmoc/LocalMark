# 对话与 Git 每日记录

本 Skill 同时记录两类可追溯活动：

1. **AI 对话**：每轮用户输入、AI 回复、时间、设备、项目、文件改动、所用 Skill 与模型。
2. **Git 活动**：按自然日归纳的当日提交、涉及文件和工作主题。

日志保存在配置的 `log_root/YYYY/MM/YYYY-MM-DD.md`，不同项目写入同一份日文件。跨日时回填当前项目的遗漏日期：某天没有 AI 对话，只要 Git 中有当日提交，也要创建对应日志。

## 日志目录配置与移植

将下面的 `log_root` 改为集中存放日志的**现有文件夹的绝对路径**；它就是日志根目录，不再额外拼接“对话日志”。复制到其他项目时保留或更新此配置。

```yaml
log_root: 'D:/Software/ObsidianSyncVault/快捷指令/对话日志'
```

- 整个 Skill 文件夹（含 `scripts/`）可以复制到其他项目的 `.agents/skills/conversation-topic-logger/`，也可以安装到用户级 Skill 目录。脚本路径一律相对**本次实际读取的 SKILL.md 所在目录**解析，不依赖当前工作目录。
- 要求每轮强制记录的项目，应在该项目 `AGENTS.md` 中写明：每次用户回合在最终回复前读取并执行此 Skill，失败时说明原因。仅复制 Skill 不等于所有项目都会强制触发。
- 写入前检查：`log_root` 非空、为绝对路径、已存在且是文件夹，并解析为规范绝对路径。不要把相对路径默认为当前项目路径。
- 配置缺失、为空、路径不存在或指向文件时，停止本轮日志写入并提示：“对话日志目录未配置或无效：<路径或未配置>。请更新 Skill 的 log_root，或指定一个已存在的日志文件夹。”不得自动创建根目录或静默回退到项目目录。用户指定有效目录后再继续；只有用户要求保存配置时才更新本文件。
- 根目录有效后可以创建其下的年份、月份目录；历史日志不因修改配置自动迁移，本 Skill 合并的是后续写入的记录。

### 路径配置与沙箱权限

配置路径不会授予文件系统权限。目录存在也不代表可写；按当前会话的实际权限执行。

- unrestricted / danger-full-access 环境通常可以写项目外目录，但仍受操作系统权限限制。
- 在受限环境中，集中日志目录可能需要纳入允许写入的目录；Skill 无法自行扩大沙箱权限。
- 若检查或写入被拒绝，说明被拒绝的实际路径和错误，提醒用户将该目录加入允许写入范围，或指定可写目录；若当前环境支持审批则遵循其机制。不要改成其他目录、绕过限制或自动关闭沙箱。
- 路径或权限问题只阻止日志步骤，不能无限重试或阻止用户原任务的回复；最终回复明确说明本轮未记入日志以及原因。

### 多项目合并与并发

- **来源项目**取当前任务工作区，与日志目录、Skill 安装目录分开。Git 采集始终显式传入来源仓库 `RepositoryRoot`，不能采集集中日志目录所属仓库来代替当前项目。
- 项目名供阅读；规范化的来源仓库绝对路径作为项目标识。非 Git 项目使用工作区绝对路径。回合记录增加来源路径，避免同名项目混淆；不同设备路径默认分别记录，不猜测它们是同一项目。
- 同日日文件的回合号全局递增。追加、历史 Git 段替换与月总结更新必须串行进行：在日志根目录打开 `.conversation-topic-logger.lock`（`OpenOrCreate`、`ReadWrite`、`FileShare.None`），持有文件句柄期间重新读取目标文件，再计算回合号并写入、回读验证，最后在 `finally` 中释放句柄。锁文件保留即可，存在不代表被占用，不要删除它来抢锁。
- 所有使用此目录的项目都需使用此版本的锁协议。锁占用时最多短暂重试 3 次，仍失败则报告本轮未记入；访问被拒绝立即报告。不同设备经云盘同步不具备可靠的跨设备锁，可能产生同步冲突，不能宣称此协议解决了跨设备并发。
- Git 数据可以在持锁前采集，但合并、标题和月总结必须基于持锁后重新读取的最新日志；只替换当前项目的 Git 子段，保留其他项目及全部历史回合。

## 触发方式

- **每次必执行**：每个用户回合都必须执行，不依赖 Skill 的隐式语义匹配。
- 必须在发送 `final` 前完成跨日补齐和本轮追加。
- 正常情况下日志落盘并验证成功后才结束本轮；路径、权限或锁失败时按上述规则提醒并结束，不把失败声称为成功。

## 能力边界

- Git 日总结以**提交者时间（committer date）**和当前设备时区归日，扫描本地仓库所有可达引用（`git log --all`）。
- 未提交改动没有可靠的历史日期，**不能事后精确归属到过去某天**，因此不进入历史 Git 日总结。本轮由 AI 实际创建/修改的未提交文件，仍记在对话回合的「文件」字段。
- Skill 只能在 Agent 被触发时运行。无 AI 对话的日期会在**下一次运行时追溯补齐**；若要每天零点前后立即生成，需另行配置定时任务。

## 目录结构

```text
<log_root>/
└── 2026/
    ├── 08/
    │   ├── 2026-08-29.md
    │   └── _2026-08 月度总结.md
    └── 09/
        └── 2026-09-01.md
```

- 日文件：`<log_root>/YYYY/MM/YYYY-MM-DD.md`
- 月文件：`<log_root>/YYYY/MM/_YYYY-MM 月度总结.md`
- 仅在已验证的根目录下创建年月子目录；月份补零为两位数。

## 每轮执行步骤

1. **检查配置和确定时间**：先验证 `log_root` 与当前权限，再获取本地日期和时间（`YYYY-MM-DD HH:mm:ss`），并记录时区。
2. **获取设备名**：执行 `hostname`，失败写 `未知设备`。
3. **获取仓库与项目名**：执行 `git rev-parse --show-toplevel`；项目名取根目录最后一级。非 Git 仓库则用工作区或当前目录名。
4. **补齐过去日期**：在写入今日回合前，执行当前来源项目的「跨日补齐」；所有共享文件更新遵循锁协议。非 Git 项目只记对话，不把无法采集 Git 记为“无提交”。
5. **总结用户消息**：用 1–2 句概括本轮用户输入。
6. **总结 AI 回复**：用 1–2 句概括实际完成的工作和回复结论。
7. **收集本轮文件改动**：记录本轮创建/修改的文件及一句说明；不记录对话日志自身的例行追加。
8. **记录 Skill 与环境**：只写本轮实际加载/使用的 Skill，并按「环境字段」确定 AI 和模型。
9. **追加今日回合**：若今日文件不存在，先创建标题；再按「对话回合格式」追加。
10. **验证**：重新读取今日文件，确认本轮已存在、回合号唯一且 Markdown 结构完整。

## 跨日补齐

每次运行时，在今日回合落盘前检查尚未完结的过去日期。

### 1. 确定扫描起点

- 先查找带有**当前项目标识**的最新 Git 子段，把该日作为扫描起点，重查到昨天（包含两端）；不得使用其他项目的完成日期。重查起点日可以吸收后来 fetch/合并后新变得可达的同日提交。
- **首次启用 Git 日结**（所有日志都没有该标题）时：优先从“当前月最早日志之前、日期最新的那份日志”开始。这能补齐最近一次跨月空档，又不会自动回写整个仓库历史。
- 首次启用时若找不到上述跨月前驱，则从今天之前最新的当前项目日志开始；若当前项目没有任何日志，只检查昨天。这里的历史日志、跨月前驱均只看当前项目，不能因集中目录有其他项目的旧记录而扫描其历史范围。
- 无论今天的日志是否已存在，都不得把“今天已有日志”当作昨天已完结的证据。

### 2. 采集每日 Git 活动

优先运行 Skill 自带的只读脚本：

```powershell
& (Join-Path $skillRoot 'scripts/Get-DailyGitActivity.ps1') -Date '2026-08-29' -RepositoryRoot $sourceRoot
```

其中 `$skillRoot` 是实际 Skill 文件夹绝对路径，`$sourceRoot` 是当前任务来源仓库绝对路径。脚本输出 JSON，包含当日提交哈希、提交者时间、作者、主题及 `numstat` 文件变动。它只读取 Git，不会改动工作树。

如果脚本不可用，手工执行等价的 `git -C <来源仓库> log --all --since=<当日起点> --before=<次日起点> --numstat`，并按提交者时间复核归属日期。采集报错不能写成“当日无 Git 提交”。

### 3. 按日补齐

对扫描范围内的每个日期 `D`：

- **有日志 + 有 Git 提交**：在文件末尾新增或更新唯一的 `## 当日 Git 改动`。
- **有日志 + 无 Git 提交**：写入 `## 当日 Git 改动` 和 `- 当日无 Git 提交记录。`，标记该日已完结。
- **无日志 + 有 Git 提交**：新建 `D.md`，写入标题、`> 当日无 AI 对话记录。` 和 Git 段。
- **无日志 + 无 Git 提交**：跳过，不创建空日志。
- 同一日只能有一个 `## 当日 Git 改动`，其下按项目建立子段；重新执行只替换当前项目子段，不得覆盖其他项目或重复追加。同日已存在其他项目的对话时，不写“当日无 AI 对话记录”。
- 旧版无项目标识的 Git 段：只有根据原日志位置和来源记录能确认归属时，才为其补充项目子标题与来源路径，保留原内容；无法确认则保留为“历史来源未标注”，不得当作当前项目已完成的证据。旧对话回合原样保留。

Git 段格式：

```markdown
## 当日 Git 改动

### 项目：示例项目

- **来源**：`D:/Projects/example`
- **统计时区**：Asia/Shanghai
- **概览**：2 个提交，涉及 3 个文件；主要完成 Spiritfarer 笔记归档与影视笔记更新。
- **23:01 `9db6def`**：Spiritfarer 笔记
  - 新增 `Spiritfarer.md`
  - 修改 `电影/biji 3.md`
- **23:16 `edac521`**：合并远程分支（合并提交未产生额外文件变动）
```

写作要求：

- 保留每个提交的短哈希、时间和原始主题，便于回查。
- 文件路径较多时按工作主题归纳，但不得编造 Git 中不存在的改动。
- `对话日志/` 的例行变动可保留在提交文件清单中，但不作为日标题的主要关键词，除非当天工作本身就是日志系统维护。

### 4. 生成每日标题总结

对已完结的过去日期，结合**对话回合 + Git 改动**做主题聚类与去噪，提取 3–5 个关键词写入标题：

```markdown
# 2026-08-29 每日总结（Spiritfarer 笔记、影视笔记、Git 合并）
```

- 同一主题的多轮对话/多个提交合并成一个关键词。
- 问候、确认、致谢、例行日志文件更新等低信息内容不占主题位。
- 旧标题已带关键词时，若本次新增了 Git 段，必须基于两类内容**重新计算并替换**，不能因为存在 `（`就跳过。

## 对话回合格式

```markdown
### 回合 N | HH:mm | 设备名 | 项目名
- **来源**：`D:/Projects/example` | 时区=Asia/Shanghai
- **用户**：[用户消息概括]
- **回复**：[AI 实际输出与完成事项概括]
- **文件**：
  - 新增 `path/to/a.md`：生成内容概要
  - 修改 `path/to/b.md`：改动内容概要
- **Skill**：conversation-topic-logger、skill-creator
- **环境**：AI=Codex | 模型=gpt-5.6-sol
---
```

- 回合号 `N` 是当日 AI 对话记录序号，从 1 递增；Git 段不计入回合号。
- 文件路径相对来源项目根目录；项目外文件写绝对路径。本轮无文件操作则整行省略。
- 不记录对话日志自身的例行追加，避免套娃。
- Skill 字段只记本轮实际使用的技能；未使用则省略。

今日文件首次创建时，标题先使用：

```markdown
# YYYY-MM-DD 每日记录
```

今日未结束前不必预写关键词，由下一次跨日补齐统一完结。

## 月度总结

进入新月份的首次运行时，先完成上月所有需要补齐的日志，再创建或刷新上月 `_YYYY-MM 月度总结.md`。

集中目录中的日标题和月度总结聚合所有项目，不仅是当前项目。Git 完结与覆盖范围仍按项目记录；当前项目的扫描完成不表示其他项目已补齐。Git 活跃天数按日期去重，不能把各项目天数直接相加；列出各项目实际覆盖范围。

月度总结必须聚合当月全部日文件中的：

- 每日标题关键词。
- AI 对话中的主题、结论和产出。
- Git 提交中的工作主题和文件改动。
- AI 对话活跃天数、Git 活跃天数和总记录天数。

格式：

```markdown
# 2026-08 每月总结

> 生成于：2026-09-01（跨月时自动补写）

## 本月概览
- 总记录天数：22 天
- AI 对话活跃：20 天
- Git 活跃：18 天
- 主要主题：`关键词1`、`关键词2`、`关键词3`
- 主要产出：……

## 每日要点
- **08-29**：`Spiritfarer 笔记`、`Git 合并` — 当日无 AI 对话，完成笔记新增与合并。
```

更新规则：

- 月总结不存在时新建。
- 若补录了该月 Git-only 日志、更新了任一日 Git 段，或日文件数/活跃天数与现有月总结不一致，必须重新聚合并更新月总结；不能因为文件已存在就跳过。
- 首次启用 Git 日结时若只迁移了历史月份的局部日期，月总结必须明确写出 `Git 统计覆盖：YYYY-MM-DD 至 YYYY-MM-DD`，且不得把局部活跃天数表述为整月完整统计。
- 不改写已有日志的对话回合，只补 Git 段、标题关键词和受影响的月总结。

## 环境字段

| 字段 | 获取方式 | 失败兜底 |
|---|---|---|
| AI | 只写 `Codex`、`DSH（DeepSeek Harness）` 或 `Claude Code`；存在 `$DSH_WEB_URL` / `$DSH_SESSION_ID` 时写 DSH，否则按实际会话环境写 | `未知 AI` |
| 模型 | 使用当前会话运行记录里的完整模型 ID，不把默认配置当作实际模型 | `未知模型` |

### Codex

从当前会话 JSONL 最后一条 `turn_context.payload.model` 取值。会话 ID 优先使用 `$CODEX_SESSION_ID`，其次 `$CODEX_THREAD_ID`；只能读取与当前会话 ID 匹配的 JSONL，禁止直接取 `~/.codex/sessions/` 下的“最新文件”。无法确定时写 `未知模型`。

### DSH（DeepSeek Harness）

从 `$DSH_SESSION_JSONL` 检索 `"model":"..."` 并取出现次数最多的值；`.zstd` 先用 `zstdcat` 解压到标准输出。失败写 `未知模型`。

### Claude Code

从当前活动 transcript 最后一条 `type="assistant"` 记录的 `message.model` 取值。优先使用 hook 输入中的 `transcript_path`；并行会话无法唯一定位时不得猜测，写 `未知模型`。

## 注意事项

- 跨日补齐按“自然日”而不是“上一份对话日志”处理，不得跳过中间的 Git-only 日期。
- 日标题和月度总结都必须同时考虑 AI 对话与 Git 改动。
- 低价值对话仍按回合记录，但不强行进入每日关键词。
- 对历史文件采用幂等更新：Git 段替换而非重复追加，回合号不重排，对话原文不改写。
