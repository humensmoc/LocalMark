# 对话记录与总结

本 Skill 只记录 AI 对话：每轮用户输入、AI 回复、时间、设备、项目、文件改动、所用 Skill 与模型。

日志保存在配置的 `log_root/YYYY/MM/YYYY-MM-DD.md`，不同项目写入同一份日文件。只记录实际发生的 AI 对话，不创建没有 AI 对话的日期日志。过去日期的每日标题和月度总结只依据对话回合生成，不采集 Git 提交，也不生成 Git 日结。

## 日志目录配置与移植

日志根目录是集中存放日志的**现有文件夹的绝对路径**；它就是日志根目录，不再额外拼接“对话日志”。公司 Windows 和家里 Mac 可以使用各自的绝对路径，多个仓库共享同一台设备的本地配置。

已启用项目在每轮记录前，先在**本次实际读取的 SKILL.md 所在目录**执行：

```text
python scripts/logger_setup.py resolve
```

在 PowerShell 中可用 `python`，在 Mac 终端中可用 `python3`；运行时应将脚本路径写成相对于 Skill 目录的实际路径。成功时 JSON 给出 `log_root`、设备名和来源。解析顺序为：非空的 `CONVERSATION_LOG_ROOT` 环境变量 > 当本副本的 `routes.json` 设置 `prefer_device_route: true` 且当前设备命中映射时使用该映射 > 本机 `~/.conversation-topic-logger/config.json` 的 `log_root` > 其余情况下 `routes.json` 中当前 hostname 的映射。已确认写入主 Vault 共享日志的项目使用固定设备映射，以免其他项目的本机配置改写目标。设备名转小写并去掉末尾 `.local`。一旦选中候选，就验证其为存在、可写的绝对目录；无效时不回退到其他候选，尤其不能拿另一台设备的路径写日志。没有跨设备兜底值。

- 当前设备没有路径，或选中的路径不存在、不可写时，**询问用户是否需要为这台设备配置新的日志目录**，并给出当前设备名、候选路径与错误。只有用户提供或确认目录后才运行 `configure --path <绝对路径>`；用户明确要求创建新目录时才加 `--create`。若失效来源是 `CONVERSATION_LOG_ROOT`，先让用户修正或清除该环境变量，因为它会覆盖本地配置。本轮不能落盘则在最终回复中说明原因，不无限重试。
- `configure` 只更新当前设备的 `~/.conversation-topic-logger/config.json`，不会修改仓库中的路由。配置可用 `CONVERSATION_LOG_CONFIG_FILE` 指定其他本机文件；历史日志不会自动迁移。目录有效后可创建其下的年份、月份目录。固定路由已命中时，本机配置不会覆盖它；临时改用另一目录时可设置 `CONVERSATION_LOG_ROOT`。
- 对固定写入主 Vault 共享日志的已知设备，修改路径时更新 `routes.json` 中对应映射；其他安装副本若没有固定路由，可用 `configure`。不要把相对路径默认为当前项目路径。

### 其他仓库一键接入

主 Vault 是受 Git 跟踪的 Skill 源，保留本项目的 `AGENTS.md`、Cursor 规则和对话日志，本项目无需运行 `install`。每台电脑从主 Vault 的 Skill 目录运行一次 `python scripts/logger_setup.py register`（Mac 用 `python3`）；若 Vault Sync 未带来隐藏的 `.agents` 目录，先通过主 Vault 的 Git 仓库取得它。这会把 Skill 注册到用户级 Codex 和 Cursor 目录，使其他仓库中的 Agent 也能发现安装能力。用户级注册本身**不要求所有仓库逐回合写日志**；只有主 Vault 的共享规则或其他仓库的本地规则启用后才强制记录。

之后用户在其他仓库说“给当前仓库启用对话日志”，Agent 应从**当前任务的 Git 仓库根目录**运行用户级 `scripts/logger_setup.py install`，不让用户寻找 Vault 路径或填写仓库地址。`install` 省略 `--repo` 时自动识别当前 Git 仓库；也支持 `--repo "<目标仓库绝对路径>"` 指定其他 Git 仓库。命令复制 Skill 与脚本，在目标 `AGENTS.override.md` 添加强制规则，并安装 Cursor 的 `alwaysApply` 规则；同时将这三个本地文件路径写入该仓库的 `.git/info/exclude`，使接入后 `git status` 保持干净，不把个人日志约束交给协作者。相同内容重复安装为成功的无操作；目标 Skill 与来源不同则先检查差异，确认更新后加 `--update`。已有仓库内容保留。

`.git/info/exclude` 只忽略未跟踪文件。旧仓库若已将日志 Skill、Cursor 规则或含日志约束的 `AGENTS.md` 纳入 Git，须先将这些文件从 Git 索引移出，再使用本地 override；不能声称仅添加忽略规则就已消除对协作者的影响。Codex 在同一目录优先读取 `AGENTS.override.md`；Cursor 的本地规则负责 Cursor 会话。

安装后立即在目标仓库执行 `resolve` 检查此设备的日志目录。若没有有效目录，按上文询问用户，完成设备配置后再记录本轮。Mac 需在那台电脑注册一次；仅有 Windows 上的用户级安装不会自动出现在 Mac 的用户主目录。

### 路径配置与沙箱权限

配置路径不会授予文件系统权限。目录存在也不代表可写；按当前会话的实际权限执行。

- unrestricted / danger-full-access 环境通常可以写项目外目录，但仍受操作系统权限限制。
- 在受限环境中，集中日志目录可能需要纳入允许写入的目录；Skill 无法自行扩大沙箱权限。
- 若检查或写入被拒绝，说明被拒绝的实际路径和错误，提醒用户将该目录加入允许写入范围，或指定可写目录；若当前环境支持审批则遵循其机制。不要改成其他目录、绕过限制或自动关闭沙箱。
- 路径或权限问题只阻止日志步骤，不能无限重试或阻止用户原任务的回复；最终回复明确说明本轮未记入日志以及原因。

### 多项目合并与并发

- **来源项目**取当前任务工作区，与日志目录、Skill 安装目录分开。
- 项目名供阅读；规范化的来源仓库绝对路径作为项目标识。非仓库项目使用工作区绝对路径。回合记录增加来源路径，避免同名项目混淆；不同设备路径默认分别记录，不猜测它们是同一项目。
- 同日日文件的回合号全局递增。回合追加、每日标题和月度总结更新必须串行进行：在日志根目录打开 `.conversation-topic-logger.lock`（`OpenOrCreate`、`ReadWrite`、`FileShare.None`），持有文件句柄期间重新读取相关文件，再计算回合号或汇总内容并写入、回读验证，最后在 `finally` 中释放句柄。锁文件保留即可，存在不代表被占用，不要删除它来抢锁。
- 所有使用此目录的项目都需使用此版本的锁协议。锁占用时最多短暂重试 3 次，仍失败则报告本轮未记入；访问被拒绝立即报告。不同设备经云盘同步不具备可靠的跨设备锁，可能产生同步冲突，不能宣称此协议解决了跨设备并发。
- 每日标题和月度总结汇总集中目录内所有项目的对话；已有日志中的历史 Git 段保持原样，不作为新总结的数据来源，也不因恢复总结功能而重写。

## 触发方式

- **已启用项目每次必执行**：主 Vault 的 `AGENTS.md`，或其他仓库的本地 `AGENTS.override.md` / Cursor 规则要求逐回合记录时，每个用户回合都必须执行，不依赖 Skill 的隐式语义匹配。用户级安装仅提供接入入口。
- 必须在发送 `final` 前完成适用的跨日、跨月总结和本轮追加。
- 正常情况下日志落盘并验证成功后才结束本轮；路径、权限或锁失败时按上述规则提醒并结束，不把失败声称为成功。

## 能力边界

- Skill 只能在 Agent 被触发时运行。已发生 AI 对话的过去日期会在**下一次运行时追溯完成每日标题**；无 AI 对话的日期不创建日志。若要每天零点前后立即生成，需另行配置定时任务。

## 目录结构

```text
<log_root>/
└── 2026/
    ├── 08/
    │   ├── 2026-08-29.md
    │   └── _2026-08 月度总结.md
    └── 09/
        └── 2026-09-01.md
```

- 日文件：`<log_root>/YYYY/MM/YYYY-MM-DD.md`
- 月文件：`<log_root>/YYYY/MM/_YYYY-MM 月度总结.md`
- 仅在已验证的根目录下创建年月子目录；月份补零为两位数。

## 每轮执行步骤

1. **解析日志根目录并确定时间**：运行 `scripts/logger_setup.py resolve`，用其验证后的 `log_root`；失败时按上文询问当前设备的新目录。成功后获取本地日期和时间（`YYYY-MM-DD HH:mm:ss`），并记录时区。
2. **获取设备名**：macOS 优先执行 `scutil --get LocalHostName` 获取本地计算机名，失败后回退到 `socket.gethostname()`；Windows 和其他系统使用 `socket.gethostname()`。两者都失败时写 `未知设备`。
3. **获取项目与来源路径**：执行 `git rev-parse --show-toplevel`；项目名取根目录最后一级。非仓库项目则用工作区或当前目录名。
4. **完成过去日期的对话总结**：按「每日与月度总结」处理尚未完成的日标题和上月总结；不回溯修改历史对话回合或 Git 段。
5. **原文记录用户消息**：按「用户原文规则」逐字照录本轮用户输入，不概括、不压缩；有图片时另写简短的图片说明。
6. **总结 AI 回复**：用 1–2 句概括实际完成的工作和回复结论。
7. **收集本轮文件改动**：记录本轮创建/修改的文件及一句说明；不记录对话日志自身的例行追加。
8. **记录 Skill 与环境**：只写本轮实际加载/使用的 Skill，并按「环境字段」确定 AI 和模型。
9. **追加今日回合**：若今日文件不存在，先创建标题；再按「对话回合格式」追加。
10. **验证**：重新读取今日文件，确认本轮已存在、回合号唯一且 Markdown 结构完整；如更新了日标题或月总结，也回读核对。

## 每日与月度总结

每次运行时，在写入今日回合前检查日志根目录中已存在的日文件。只读取对话回合的用户、回复和文件字段来提炼主题与产出；历史 `## 当日 Git 改动` 段及 Git 提交不参与统计。扫描和汇总按日志文件的自然日期，而不是来源项目的 Git 仓库日期。

### 跨日完成每日标题

- 扫描截至昨天已存在的日文件，找出仍使用 `# YYYY-MM-DD 每日记录` 或旧式无关键词标题的文件。已有关键词的每日总结标题保持原样，不因恢复本功能而批量重写历史。
- 每份日文件只依据其中全部项目的 AI 对话回合做主题聚类、去噪，提取 3–5 个关键词；内容不足时使用实际能支持的数量，不编造主题。问候、确认、致谢和例行日志维护不占主题位。
- 在共享锁内重读日文件，仅替换第一行标题为 `# YYYY-MM-DD 每日总结（关键词1、关键词2）`；保留全部回合、图片说明和历史 Git 段。若当天无对话回合，不生成每日总结。
- 日标题已完成时重复运行不追加第二个标题。今天尚未结束，保持 `# YYYY-MM-DD 每日记录`，由后续跨日运行完成。

### 跨月生成与更新月度总结

- 进入新月份的首次运行时，完成上月全部已有日文件的标题，再创建或更新上月的 `_YYYY-MM 月度总结.md`。若之后补录了该月 AI 对话，或补齐了该月日标题，也应更新受影响的月总结。没有日文件的月份不建空月总结。
- 汇总该月全部日文件中所有项目的 AI 对话：日标题关键词、用户讨论的主题、回复中的结论和「文件」字段中的产出。统计有 AI 对话的日数与回合数；历史 Git-only 日文件不计入。既有 Git 日结和提交内容不进入新的月总结统计。
- 月总结包含「本月概览」和「每日要点」；每天只写一次主题，有独立结论或产出时再补具体内容，不重复复述关键词。先在共享锁内重读日文件和已有月文件，再写入并回读验证；未发生相关对话变化时保持文件不变。
- 不自动删除或重写过去含 Git 统计的月总结。确需重算旧月份时，保留已有非 Git 内容，只更新有证据支持的 AI 对话部分，并明确统计口径。

格式示例：

```markdown
# 2026-08 对话月度总结

> 生成于：2026-09-01（跨月时自动补写）

## 本月概览
- AI 对话活跃：20 天，合计 216 回合
- 主要主题：`关键词1`、`关键词2`、`关键词3`
- 主要产出：……

## 每日要点
- **08-29**：`主题1`、`主题2` — 当天的具体结论或产出。
```

## 对话回合格式

```markdown
### 回合 N | HH:mm | 设备名 | 项目名
- **来源**：`D:/Projects/example` | 时区=Asia/Shanghai
- **用户**：
  > [用户消息原文第一行]
  > [用户消息原文第二行]
- **图片说明**：图 1：截图中可见的主要内容。
- **回复**：[AI 实际输出与完成事项概括]
- **文件**：
  - 新增 `path/to/a.md`：生成内容概要
  - 修改 `path/to/b.md`：改动内容概要
- **Skill**：conversation-topic-logger、skill-creator
- **环境**：AI=Codex | 模型=gpt-5.6-sol
---
```

- 回合号 `N` 是当日 AI 对话记录序号，从 1 递增。
- 文件路径相对来源项目根目录；项目外文件写绝对路径。本轮无文件操作则整行省略。
- 不记录对话日志自身的例行追加，避免套娃。
- Skill 字段只记本轮实际使用的技能；未使用则省略。

### 用户原文规则

用户输入是日志中最重要的部分，必须完整保留；只有「回复」字段做概括。

- 逐字照录本轮用户输入：不概括、不删减、不润色，错别字、口语、标点和中英混写都保持原样。
- 每一行原文前加 `  > `（两个空格缩进 + 引用符）；空行写成 `  >`，保留原有换行和段落。
- 用户粘贴的长文本、代码、日志、链接同样全文照录；原文里的代码块围栏也放在引用行内，原样保留。
- 图片、文件附件等无法以文本记录的内容，在对应位置写 `[图片]`、`[附件：文件名]`。
- 用户消息含图片时，保留原文中的 `[图片]` 占位符，并在引用块之后、`回复` 字段之前单独增加 `**图片说明**`。按出现顺序标为“图 1”“图 2”等；每张图用 1–2 句客观描述与本轮问题有关的可见内容，必要时摘录清晰可辨的关键文字或数值。图片说明是补充信息，不替代或改写用户原文。
- 只根据本轮实际可见的图片内容描述；不要从用户提问、AI 回复或文件名反推图片内容，不确定的细节不要猜。图片无法读取或内容无法辨认时写明“图 N：图片内容无法辨认”。无图片时省略 `图片说明` 字段。
- 只记录用户本人输入的内容；客户端或 hook 自动注入的系统提醒、IDE 上下文、环境信息不属于用户输入，不记录。
- 用户通过斜杠命令调用 Skill 时，记录用户实际输入的命令及参数原文。

今日文件首次创建时，标题先使用：

```markdown
# YYYY-MM-DD 每日记录
```

今日未结束前不预写关键词，由之后的跨日运行完成每日总结。

## 环境字段

| 字段 | 获取方式 | 失败兜底 |
|---|---|---|
| AI | 只写 `Codex`、`DSH（DeepSeek Harness）` 或 `Claude Code`；存在 `$DSH_WEB_URL` / `$DSH_SESSION_ID` 时写 DSH，否则按实际会话环境写 | `未知 AI` |
| 模型 | 使用当前会话运行记录里的完整模型 ID，不把默认配置当作实际模型 | `未知模型` |

### Codex

从当前会话 JSONL 最后一条 `turn_context.payload.model` 取值。会话 ID 优先使用 `$CODEX_SESSION_ID`，其次 `$CODEX_THREAD_ID`；只能读取与当前会话 ID 匹配的 JSONL，禁止直接取 `~/.codex/sessions/` 下的“最新文件”。无法确定时写 `未知模型`。

### DSH（DeepSeek Harness）

从 `$DSH_SESSION_JSONL` 检索 `"model":"..."` 并取出现次数最多的值；`.zstd` 先用 `zstdcat` 解压到标准输出。失败写 `未知模型`。

### Claude Code

从当前活动 transcript 最后一条 `type="assistant"` 记录的 `message.model` 取值。优先使用 hook 输入中的 `transcript_path`；并行会话无法唯一定位时不得猜测，写 `未知模型`。

## 注意事项

- 低价值对话仍按回合记录，但不强行进入每日或月度关键词。
- 历史对话回合只追加、不改写；每日总结仅替换未完成的标题，月度总结仅在跨月或相关 AI 对话补录时更新。历史 Git 段保持原样。
