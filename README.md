# 本地摘录 · Web Clipper

面向桌面 Chrome 的本地网页批注插件。选中文字即可高亮、写评论；在侧栏给整个网页添加多个标签。每篇网页自动生成一个 Markdown，JSON 保存完整标注和定位信息。无账号、无批注服务器、无需安装本地辅助程序。

## 安装现成版本

当前版本为 **0.2.0**。仪表盘支持分类与标签管理、文章多选和批量整理，分类与标签使用稳定 ID 关联。更新后重新加载扩展并刷新网页，底部应显示「侧栏 0.2.0 · 网页 0.2.0」，仪表盘显示 v0.2.0。旧数据首次读取时自动迁移为 v2，并生成「分类标签.json」。

1. 在 Chrome 地址栏输入 `chrome://extensions`，打开右上角「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择本项目的 **`dist` 文件夹**，不要选择项目根目录。
3. 在工具栏的扩展菜单中固定「本地摘录 · Web Clipper」。
4. 打开一个普通网页，点击插件图标，在左侧栏底部点击齿轮加文字的「设置」按钮；也可右键浏览器工具栏的插件图标选择「选项」，或在扩展详情页打开「扩展程序选项」。底部仅一行显示目录、保存状态、仪表盘和设置；目录或状态过长时悬停可查看完整文字。
5. 在设置页点击「选择文件夹」，选择一个专用摘录目录并允许读写。可以选择 Obsidian Vault 中的子文件夹。
6. 安装前已打开的网页建议刷新一次。更新插件时在扩展管理页点击刷新，并刷新网页。

当前构建已在 Chrome 128.0.6613.114 与 Chrome for Testing 153 中进行扩展集成测试。最低支持 Chrome 128：旧版通过关闭原生侧栏文档来收起侧栏，支持新关闭接口的浏览器使用该接口。无需运行 Node 或保持设置页打开，后台服务负责保存。

## 操作

| 操作 | 效果 |
| --- | --- |
| 选中文字后快速点击鼠标松开位置旁的笔形图标 | 使用最近一次颜色保存，首次默认为黄色 |
| 悬停高亮按钮约 350ms | 展开颜色和批注编辑窗 |
| 悬停左边缘彩色位置条 | 预览该条摘录及批注（如有），支持移入预览滚动阅读 |
| Enter / Shift+Enter / Esc | 保存 / 批注换行 / 取消；输入法选字不触发保存 |
| 悬停原文高亮 | 显示批注；点击进入编辑 |
| 点击重叠高亮 | 选择要编辑的标注 |
| 点击插件图标 | 打开或收起浏览器原生侧栏 |
| Ctrl+B（Mac：Cmd+B） | 浏览器处于前台时打开或关闭原生侧栏；输入框中也生效，此组合键将用于侧栏开关 |
| 点击侧栏摘录或左侧彩色轨迹 | 滚动定位并短暂强调原文 |
| 点击「链接」 | 复制 Chrome/Edge 原生文本定位链接；接收者可定位高亮，但不会看到批注 |
| 点击「未定位 · 重新绑定」 | 重新选择文字后确认，保留原标注 ID、评论、标签和颜色 |

侧栏顶部将「最近网页」「标签」「当前页面」与小号关闭按钮放在同一行，去掉单独的品牌标题区。每个已保存网页始终有一个主分类，另有零到多个小标签；主分类在顶部单选，支持搜索、新建与查看同类网页。预置未分类、游戏设计、交互设计、视觉设计、游戏营销、游戏分析、访谈；旧数据迁移为“未分类”，原标签全部保留为小标签，之后可自行选择实际主分类。小标签仍使用“+”搜索、新建和多选；空搜索列出全部已有小标签，按关联网页数量排序并显示计数。主分类与小标签各自独立，不根据主分类限制小标签。标签页上方为紧凑横向换行的筛选区，下方为独立滚动的网页卡片。主分类单选，小标签多选且同时满足，搜索与筛选条件叠加；再次点击可取消条件，也可清空筛选。标签数字表示当前其他条件下的匹配网页数，数量为 0 的主分类和小标签自动隐藏。卡片显示完整标题、分类标签、单行评论预览和可展开摘录；评论超出一行时显示省略号，并仅在实际截断时提供“查看完整评论”。卡片不显示网址、日期或“网页评论”标题，未筛选时显示全部网页。分类信息随逐页 JSON 保存，读回后重建已使用的分类与标签。侧栏占用浏览器分配的独立区域，网页在剩余视口中重新排版，关闭后恢复。左右位置由浏览器设置决定：在 Chrome 设置的「外观」中将侧栏位置设为左侧，即可让网页向右腾位。Ctrl+B 未生效时，在 `chrome://extensions/shortcuts` 检查「本地摘录」的「激活扩展程序」是否绑定为 Ctrl+B，并处理其他扩展的快捷键冲突。侧栏随当前窗口的活动标签页切换；在浏览器内部页只显示不可摘录提示，仍可浏览已保存的文章。未保存的标题和评论草稿在同一次浏览器会话中可跨侧栏关闭恢复；重启浏览器或重载扩展前请先保存。

## 本地数据

### 文章管理大窗口

点击侧栏底部、设置旁边的「仪表盘」按钮，或在设置页点击「打开文章管理」。默认打开 1440 × 920 的独立窗口，可以拖动、调整大小；再次点击会聚焦已有窗口。

第一个标签页为「文章管理」，宽窗口分为三栏：左侧主分类和小标签筛选、中间文章卡片、右侧文章详情。筛选与侧栏标签页相同，支持搜索、主分类单选、小标签同时满足和清空筛选。点击整张文章卡片（标题、标签、评论或空白处）即可选择详情，不会打开原网页；展开评论和摘录的按钮仍只负责展开；需要访问来源时使用详情中的「打开原网页」。较窄窗口将筛选移到列表上方，极窄窗口按列表、详情上下排列。

- 详情直接编辑主分类、增删标签；这些操作即时保存。描述沿用已有「网页评论」字段，点击「保存评论」保存。
- 已有高亮可以修改摘录展示文字、颜色、批注或删除。编辑展示文字保留原文定位锚点与标注 ID；需要改变定位时，在原网页使用「重新绑定」。新增高亮仍需在原网页选择文字。
- 评论和高亮草稿按文章保留，切换文章、筛选或刷新本地数据不会清空；刷新或关闭管理窗口前应先保存，浏览器会对未保存编辑提示离开确认。
- 管理窗口与侧栏共用浏览器缓存、逐页 JSON 和 Markdown。窗口获得焦点或点击「刷新本地数据」时读取外部改动，可见时也每 15 秒检查一次。并发修改会保留草稿并提示冲突，文件冲突在设置中处理。
- 点击右上角「分类与标签管理」，新建、重命名、合并或删除主分类和标签。重命名保留 ID；同名重命名会明确询问是否合并。删除主分类时转入所选分类，默认转入「未分类」；「未分类」不可删除或重命名。删除标签只清理关联，文章、评论与高亮保留。空分类和空标签也会保留，默认分类只在首次初始化时提供。
- 勾选文章，或「全选当前筛选结果」，可更改主分类、批量添加或移除多个标签。添加会去重并保留原有标签，移除只影响所选文章，不删除全局标签；候选标签显示所选文章中的使用数量。改变搜索或筛选会清空选择。操作前会核对选中的关联是否已被其他窗口修改，有冲突时整个批次拒绝保存。
- 全库操作先读取本地数据并检查冲突，修改后立即保存浏览器缓存，再同步文件。界面显示实际修改数量；文件部分失败仍会显示待同步或冲突，不能仅凭浏览器保存提示视为磁盘完成。分类文件冲突在「分类与标签管理」中备份后选择保留版本。

### 网页评论

在「当前页面」的「网页评论」输入框写下整页想法，点击「保存评论」或按 Ctrl+Enter（Mac 为 Cmd+Enter）保存，Enter 可换行。清空后保存可删除评论，网页标签和高亮仍保留。未保存输入在收起侧栏、切换侧栏标签页时保留，刷新或关闭网页前请保存。评论纳入侧栏搜索，显示在最近网页和标签结果中；只在插件侧栏展示，不生成原文高亮、位置条或悬停批注。

网页评论保存为 JSON 顶层 `comment`，并在 Markdown 的网页标签后、摘录前导出；没有高亮也会生成这两份文件。旧 JSON 没有 `comment` 时按空评论处理。手动修改 JSON 的 `comment` 后刷新本地数据即可读回。多个网页标签页同时编辑时，旧输入不会覆盖最新评论；请先复制未保存输入，再使用「读取最新评论」核对。保存状态与文件冲突处理同下文。

```text
你选择的摘录目录/
├── 分类标签.json          # 分类/标签的稳定 ID 与名称
├── 网页标题.md
├── 原始数据/
│   └── 网页ID.json
└── 冲突备份/             # 仅在解决冲突时生成
```

- 每网页一份 Markdown，直接放在根目录，文件名使用网页标题，正文不再重复页面标题。顶部 YAML 属性包含 `created`、`updated`、`category`、`tags`、`source`；时间保持原 ISO 8601 UTC 值，category 为唯一主分类字符串，tags 为小标签数组。每条内容使用引用块显示高亮原文、普通段落显示非空批注，并保留定位链接；空批注省略。Windows 非法文件名字符替换为下划线，过长标题截短；同名文档冲突时追加网页 ID。
- 升级后刷新本地数据会迁移旧目录结构。只有新文档写入成功，且旧文件未被手工修改时才清理旧「标注.md」及空目录；手改内容保留并提示处理。
- 网页 JSON 与根目录「分类标签.json」共同构成主数据，备份或迁移资料库时请一同保留。旧版网页首次读取时自动迁移到稳定 ID 引用，原文章和标注 ID、评论与锚点保留。分类文件缺失、损坏或存在未知引用时会暂停相关同步并提示处理。
- JSON 是主数据；Markdown 是自动生成的阅读副本。手改 Markdown（包括 Obsidian 属性）不会同步回插件，也不会被静默覆盖。旧版未手改文件会自动升级；自定义正文或属性保留并提示处理。
- 新网页 ID 初次根据规范化 URL 的 SHA-256 前 16 位生成，此后作为固定身份保留；v2 不再要求 ID 随 URL 重算。查询参数保留，普通锚点和 Text Fragment 去除，`#/`、`#!` 路由保留。标题修改不会改变 ID 或导出文件路径。
- JSON 包含 `schemaVersion`、`id`、`url`、`originalUrl`、`title`、`favicon`、`markdownFile`、`categoryId`、`tagIds`、`category`、`tags`、`comment`、`createdAt`、`updatedAt` 和 `annotations`。`folderName` 仅用于旧目录迁移兼容；请保留这两个定位文件的字段。
- 每条标注包含 `id`、`text`、`note`、`tags`、`color`、`createdAt`、`updatedAt`、`anchor`；定位信息包括规范化引文 `exact`、前后文 `prefix/suffix`、文本位置 `start/end`、DOM 路径提示及创建时的引文出现次数。

**0.2.0 起，网页 JSON 为 schemaVersion 2：主分类修改 `categoryId`，标签修改 `tagIds`，值必须是根目录 `分类标签.json` 中存在的 ID。`category` 和 `tags` 仅为可读名称缓存，修改它们不会改变关联。重命名请修改分类文件中的 `name` 或使用仪表盘。网页评论修改 `comment`；摘录展示文字、批注与颜色修改 `annotations` 中的 `text`、`note`、`color`。** 颜色值为 `yellow`、`green`、`blue`、`pink`、`purple`。保留网页和标注 ID、URL、folderName、定位字段；要重新定位原文，请使用插件的「重新绑定」。时间使用 ISO 8601 UTC 格式。需要改变最近修改排序时，一并更新 `updatedAt`。

重开网页、打开侧栏、进入设置或点击设置中的「刷新本地数据」时检查 JSON 修改。无需手工改变 `updatedAt` 也能读回评论内容。第一版不持续监听磁盘上的外部改动；每分钟重试尚未完成的写入。

旧 Markdown 中的 `<!-- annotation:... -->` 对应 JSON 摘录 ID，是便于对照的内部标记，不是文本定位链接。HTML 注释在阅读预览中通常隐藏，在源码模式仍可见。1.0.7 不再导出这些注释，也不导出顶部的 `local-web-clipper` 注释；完整 ID 和定位信息仍保存在 JSON，回到原文链接保持不变。同步按完整已知导出内容识别文件，不只依赖注释标记。

## 保存状态与冲突

- **已保存到本地文件**：JSON 与 Markdown 均同步完成。
- **已暂存浏览器 / 待同步**：内容已写入 IndexedDB，但尚未写入文件。请勿在同步完成前卸载插件或清除插件数据。
- **权限失效**：点击侧栏底部「设置」，在设置页点击「重新授权」并允许读写；成功后自动补写暂存标注。如果旧目录已移动或授权仍失败，点击「选择文件夹」重新选择原摘录目录。浏览器控制授权是否跨重启持久保留；插件不会绕过授权。
- **JSON 同时修改**：暂停覆盖，可查看两份内容后选择版本；被替换版本先存入「冲突备份」。
- **Markdown 手工修改**：原文件保留。可以继续不处理，或选择「备份手改内容并重新生成」。
- **JSON 错误或文件被删除**：不清空浏览器批注，不直接重建覆盖；在设置中修复文件或明确选择保留哪份数据。
- **部分写入失败**：保留待同步状态并重试，不重复追加摘录。

目录切换会把当前浏览器数据合并到新目录，旧目录不变；同一网页两份不同数据由用户选择。恢复已有数据时，安装插件后选择原目录即可读取「原始数据」下的 JSON。

多个标签页对同条标注提交旧版本时会拒绝覆盖并保留当前输入。文件写入前再次检查文件内容；但浏览器文件接口不能锁定外部编辑器，建议避免在点击同步的同时让其他程序持续改写同一个 JSON。

## 实现与权限

- `src/content.tsx`：封闭 Shadow DOM 内的 React 交互界面，选区、侧栏、轨迹与悬停窗口。
- `src/anchors.ts`：规范化文本索引、上下文消歧、动态页面恢复及 CSS Custom Highlight 绘制，不拆改原网页文本节点。
- `src/background.ts`、`src/sync.ts`：后台操作串行化、IndexedDB 持久化、外部文件检查、冲突与重试。
- `src/settings.tsx`、`src/files.ts`：用户目录授权和 File System Access API 读写。

HTTP/HTTPS 站点权限用于选区标注和重访自动恢复；`scripting` 用于对已打开网页补注入，`alarms` 用于重试同步，`unlimitedStorage` 用于本地摘录缓存。代码和界面全部随扩展打包，不远程加载执行代码，不上传批注。站点图标使用原网页提供的图标地址，浏览器可能请求该图标。

普通页面脚本不能通过 `host.shadowRoot` 直接读取批注界面。封闭 Shadow DOM 不等同于对恶意网页的完整安全隔离；网页仍控制自身布局和正文。

## 开发与测试

使用 Node.js 22，所有命令在本项目目录运行：

```powershell
npm ci
npm run build
npm test
npx playwright install chromium
npm run test:browser
npm run test:dashboard
```

构建产物位于 `dist`。构建只清理该产物目录，不修改 `doc` 或 Vault 根目录的依赖。第三方许可随产物放在 `THIRD_PARTY_NOTICES.txt`。

浏览器测试使用独立临时配置目录和本机 HTTP 测试页，不连接你的日常 Chrome 配置；通过调试协议访问封闭界面仅用于测试，不在插件中设置测试入口。浏览器文件接口测试使用 OPFS 的真实 `FileSystemDirectoryHandle`，另有真实 Windows 临时目录读写测试。**Windows 原生文件夹选择窗口及其跨重启授权仍需手动验收**，不能用 OPFS 测试替代。

测试结果和截图写入被 Git 忽略的 `test-results`。验证记录见 `TESTING.md`。

## 第一版边界

不支持 Chrome 内部页面、扩展商店、PDF、跨域 iframe、封闭 Shadow DOM 内正文或 Canvas 文字；只处理顶层普通网页。全文替换、翻译、正文删除后可能无法定位，届时保留批注并允许重新绑定。极长引文生成的 Text Fragment 链接可能受到聊天工具长度限制或目标浏览器兼容性影响。

不含全文剪藏、独立阅读器、随机回顾、AI、云同步或携带批注的分享链接。
